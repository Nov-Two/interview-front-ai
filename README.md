# AI Chat Application (Vue 3 + Vite + TS)

这是一个基于 Vue 3 生态系统构建的现代化移动端优先的 AI 聊天应用。项目采用了最新的前端技术栈，注重代码规范、性能优化和用户体验。

## 🛠 技术栈

- **核心框架**: Vue 3 (Composition API) + TypeScript
- **构建工具**: Vite 6
- **状态管理**: Pinia (模块化管理 User, Chat, Theme)
- **UI 组件库**: Vant 4 (移动端组件)
- **样式方案**: Tailwind CSS 4 (原子化 CSS) + CSS Variables (暗黑模式适配)
- **路由管理**: Vue Router 4
- **国际化**: Vue I18n (中英切换)
- **网络请求**: Axios (二次封装，支持拦截器和泛型)

## ✨ 项目亮点

### 1. 📂 聊天会话文件夹管理系统
- **创新点**: 实现了类似文件系统的聊天归档功能。
- **实现**: 虽然 UI 呈现为层级结构，但底层数据结构采用了**扁平化设计**。每个会话对象包含 `id`, `type` ('chat' | 'folder'), 和 `parentId` 字段。
- **优势**: 扁平化存储便于查找、更新和序列化（本地存储），同时通过 `computed` 属性动态过滤出当前文件夹下的内容，性能更优。

### 2. 🌗 深度定制的暗黑模式
- **全链路适配**: 不仅适配了自定义组件，还深度定制了 Vant UI 的内部样式变量。
- **实现**: 结合 Tailwind 的 `dark:` 前缀和 CSS 变量。`ThemeStore` 监听状态变化，动态修改 `document.documentElement` 的 class 和本地存储，确保刷新后状态持久化。

### 3. 🛡️ 现代化的登录交互
- **UI 设计**: 采用"毛玻璃" (Glassmorphism) 风格的模态框，而非传统的跳转页面。
- **技术细节**: 使用 `van-popup` 结合 Tailwind 的 `backdrop-blur` 实现背景模糊。解决了 Z-index 层级冲突，确保在全屏遮罩下，顶部的语言/主题切换按钮依然可交互 (`pointer-events-auto`)。

### 4. 🔧 工程化与封装
- **Axios 封装**: 采用 Class 语法封装 `Request` 类，集成了请求拦截（自动注入 Token）、响应拦截（统一错误处理/Toast 提示）和 TS 泛型支持，调用时可直接获得类型安全的返回值。
- **Hooks 抽离**: 将聊天逻辑抽离为 `useChat`，滚动逻辑抽离为 `useScroll`，实现了视图与逻辑的解耦。

## 🧩 遇到的问题与解决方案

### Q1: 如何处理聊天列表的嵌套文件夹逻辑？
- **问题**: 如果使用递归组件或深层嵌套对象，状态更新（如重命名、删除）会变得非常复杂且难以维护。
- **解决**: 采用**扁平化数据结构 + 引用索引**。所有会话都在一个数组中，通过 `parentId` 关联。合并会话时，只需更新被选中会话的 `parentId` 即可。

### Q2: 第三方组件库 (Vant) 的样式难以覆盖且暗黑模式不兼容？
- **问题**: Vant 默认样式是固定的，且部分组件在暗黑模式下对比度不够。
- **解决**: 使用 CSS 变量覆盖 Vant 的默认 Token（如 `--van-background`），并结合 Tailwind 的 `dark` 模式修饰符。对于特殊组件（如 Input），通过 `:deep()` 选择器穿透修改内部样式。

### Q3: 移动端全屏 Modal 遮挡了全局功能按钮？
- **问题**: 登录弹窗全屏覆盖，导致右上角的主题/语言切换按钮无法点击。
- **解决**: 将功能按钮的 `z-index` 设为极高（如 3000），并对按钮容器使用 `fixed` 定位。同时，利用 `pointer-events-auto` 确保点击事件能穿透透明区域或被按钮正确捕获。

## 🎤 面试主要提问点与回答指南

### 1. 为什么选择 Composition API 而不是 Options API？
- **回答**: 
  - **逻辑复用**: 可以将业务逻辑（如聊天、滚动、权限）抽离成 Hooks (`useChat`, `useAuth`)，比 Mixins 更清晰，无命名冲突。
  - **类型推导**: 对 TypeScript 支持更好，不需要复杂的 `this` 类型推断。
  - **代码组织**: 相关的代码（变量+方法）放在一起，而不是按 `data`, `methods` 分散，便于维护大型组件。

### 2. 你的 Axios 封装有什么特点？
- **回答**: 
  - 使用了 **Class 类** 进行封装，便于创建多个实例（如连接不同微服务）。
  - 支持 **TypeScript 泛型**，调用接口时如 `api.get<User>(...)` 可以直接获得 User 类型的代码提示。
  - 统一了**错误处理**，根据 HTTP 状态码（401, 403, 500）自动触发 Toast 提示或跳转登录（401 Logout）。

### 3. 项目中的文件夹功能是如何设计的？
- **回答**: 
  - 重点提到**数据扁平化**。解释为什么扁平化比树形结构更好（查找 O(1) vs O(N)，更新方便）。
  - 解释 `computed` 属性如何根据 `currentFolderId` 动态过滤展示列表。

### 4. Vue 3 的响应式原理是什么？
- **回答**: 
  - 提到 `Proxy` 替代了 Vue 2 的 `Object.defineProperty`。
  - `Proxy` 可以监听数组变化和对象新增属性，性能更好。
  - 结合本项目中的 `reactive` 和 `ref` 的使用场景进行说明。

### 5. 如何实现暗黑模式？
- **回答**: 
  - 依赖 Tailwind 的 `darkMode: 'class'` 策略。
  - 在 Pinia Store 中切换 `isDark` 状态，操作 DOM 的 `html` 标签添加/移除 `dark` 类名。
  - 使用 CSS 变量适配 Vant 组件库的颜色。
